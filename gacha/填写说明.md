# points.json 填写说明（抽卡记录抓取）

## 一、基准：必须用 1280x720 虚拟屏帧

所有坐标和颜色都以**虚拟屏原生帧**为准（就是引擎识别用的那份画面）。
物理屏截图的坐标是 1920x1080，要 ×2/3 才勉强对应，且颜色有色差——别直接量物理屏截图。

抓帧（二选一）：

```bash
# 方式一：一键脚本（抓帧 + 自动开框选工具，拖框就能读坐标）
bash _tools/pick.sh

# 方式二：手动三步
adb -s 2c92e197 shell "am start -n com.maawh.app/.MainActivity"
adb -s 2c92e197 shell "am start -n com.maawh.app/.MainActivity --activity-single-top --es entry FrameSave"
adb -s 2c92e197 exec-out run-as com.maawh.app cat files/cur_frame.jpg > gacha/frame_jilu.jpg
```

> 抓帧不会动虚拟屏里的游戏页面。所以量「四个池子选项」的坐标时：
> 先在虚拟屏里把下拉框点开（悬浮窗预览/全屏窗口里点），**保持展开状态**再抓帧。

## 二、每个字段量什么

| 字段 | 量的东西 | 形式 | 容差 |
|---|---|---|---|
| `click.dropdown` | 右上角池子下拉框按钮中心 | `[x, y]` | ±5px 无影响 |
| `click.poolOption.*` | 下拉展开后四个选项文字的中心 | `[x, y]` | ±5px 无影响 |
| `click.nextPage` / `prevPage` / `pageOne` | 底部分页栏按钮/页码的中心 | `[x, y]` | ±5px 无影响 |
| `crop.nameCol` | 名字列整条（第一行字上沿 → 最后一行字下沿） | `[x, y, w, h]` | ±几像素无影响 |
| `crop.timeCol` | 时间列整条 | `[x, y, w, h]` | 同上 |
| `crop.rarityStrip` | 只框住稀有度彩色文字的横向窄条 | `[x, y, w, h]` | 宁窄勿宽 |
| `table.fullRegion` | 整个表格大框（翻页变化检测用） | `[x, y, w, h]` | 随便框 |

### 三个 crop 矩形的唯一红线

**上边**别框进表头文字（稀有度 / 器者 / 时间），从表头分隔线下面开始；
**下边**别框进页码栏（上一页 1 2 3…），到最后一行文字下沿为止。
框进去 OCR 会把表头/页码当成记录行，稀有度竖条会吃到页码高亮色。

## 三、颜色（colors）

在 VD 帧上用取色器点「特出 / 优异 / 新生」文字笔画中心，取 RGB 填入。
图省事的话：把一张记录页 VD 帧发我，我来标定。

## 四、填完之后怎么验证 / 推送手机

```bash
adb -s 2c92e197 push gacha/points.json /data/local/tmp/
adb -s 2c92e197 shell "chmod 644 /data/local/tmp/points.json; run-as com.maawh.app sh -c 'mkdir -p files/gacha && cp /data/local/tmp/points.json files/gacha/'"
```

推送后把 `gacha/frame_jilu.jpg` 也发我一份，我在本地离线验证裁剪/取色/行定位的正确率（不点游戏、零消耗），确认无误再进入实跑。
